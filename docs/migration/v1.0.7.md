# v1.0.7 主键架构升级迁移指南

> **历史文档说明**：本项目在开源前（内部版本 v1.0.6 → v1.0.7，2026-02）进行过一次
> PostgreSQL 表结构 Breaking Change。开源版本 v1.0.0 **已自带新表结构**，全新部署
> 无需任何迁移。本文仅作为历史参考保留，以及供仍运行旧表结构的部署方参考。

## 📋 变更概述

**影响范围**: PostgreSQL 表结构 (Breaking Change)

### 主键变更
- **旧主键**: `(device_name, ip)`
- **新主键**: `(device_name, ip, mac)`

### 业务价值
| 能力 | 旧架构 | 新架构 |
|------|--------|--------|
| IP 冲突检测 | ❌ 后采集的覆盖前者 | ✅ 并存记录，可查询冲突 |
| 终端漂移追踪 | ❌ 无法关联 | ✅ 可通过 MAC 追踪轨迹 |
| 多路径可见性 | ❌ 互相覆盖 | ✅ VRRP/堆叠环境完整记录 |
| 网卡更换 | ❌ 覆盖更新 | ✅ 新旧 MAC 独立记录 |


### 3. 检查是否存在 IP 冲突

## 🔧 迁移步骤

### 步骤 1: 停止 Server 和 Collector 服务
```bash
# 在所有采集节点上执行
sudo systemctl stop arp-collector

# 在 Server 上执行
sudo systemctl stop arp-server
```

### 步骤 2: 执行主键变更
```bash
psql -h <pg-host> -U postgres -d postgres << 'EOF'
BEGIN;

-- 1. 删除旧主键
ALTER TABLE arp_entry_current DROP CONSTRAINT arp_entry_current_pkey;

-- 2. 创建新主键（三字段）
ALTER TABLE arp_entry_current ADD PRIMARY KEY (device_name, ip, mac);

-- 3. 添加 IP 索引（用于冲突检测）
CREATE INDEX IF NOT EXISTS idx_arp_entry_ip ON arp_entry_current(ip);

COMMIT;

-- 验证结果
\d arp_entry_current
EOF
```

**预期输出**:
```
Indexes:
    "arp_entry_current_pkey" PRIMARY KEY, btree (device_name, ip, mac)
    "idx_arp_entry_ip" btree (ip)
    "idx_arp_entry_mac" btree (mac)
    "idx_arp_entry_collected" btree (collected_at)
    "idx_arp_entry_created" btree (created_at)
```

### 步骤 3: 部署新版本二进制并重启
```bash
make build-static
./bin/arp_server -version   # 确认版本
sudo systemctl start arp-server
# 各采集节点分发新二进制并重启 arp-collector
```

> **注意**：更新二进制版本后必须重启服务——运行中的进程在重启前仍执行旧代码。

## 🔍 新增查询能力

### 查询 1: IP 冲突检测
```sql
-- 找出所有 IP 冲突（同一设备上，同一 IP 对应多个 MAC）
SELECT device_name, ip, COUNT(DISTINCT mac) as mac_count,
       STRING_AGG(DISTINCT mac, ', ') as macs
FROM arp_entry_current
GROUP BY device_name, ip
HAVING COUNT(DISTINCT mac) > 1
ORDER BY mac_count DESC;
```

### 查询 2: 终端漂移追踪
```sql
-- 追踪某个 MAC 地址的移动轨迹
SELECT device_name, ip, interface,
       created_at, collected_at,
       EXTRACT(EPOCH FROM (collected_at - created_at)) / 3600 as hours_alive
FROM arp_entry_current
WHERE mac = 'aa:bb:cc:dd:ee:ff'
ORDER BY collected_at DESC;
```

### 查询 3: 多路径检测
```sql
-- 找出被多个网关同时看到的终端（堆叠/VRRP 场景）
SELECT ip, mac, COUNT(DISTINCT device_name) as gateway_count,
       STRING_AGG(DISTINCT device_name, ' | ') as gateways
FROM arp_entry_current
GROUP BY ip, mac
HAVING COUNT(DISTINCT device_name) > 1
ORDER BY gateway_count DESC
LIMIT 20;
```

### 查询 4: 网卡更换历史
```sql
-- 查看某个 IP 的所有历史 MAC 记录（按时间排序）
SELECT mac, interface, created_at, collected_at,
       CASE
         WHEN collected_at > NOW() - INTERVAL '1 hour' THEN '活跃'
         ELSE '已离线'
       END as status
FROM arp_entry_current
WHERE device_name = 'your-device-name' AND ip = '192.0.2.100'
ORDER BY collected_at DESC;
```

## 🚧 回滚方案（紧急情况）

```bash
# 1. 停止服务
sudo systemctl stop arp-server arp-collector

# 2. 恢复备份
psql -h <pg-host> -U postgres -d postgres < /tmp/arp_backup_*.sql

# 3. 回滚主键
psql -h <pg-host> -U postgres -d postgres << 'EOF'
BEGIN;
ALTER TABLE arp_entry_current DROP CONSTRAINT arp_entry_current_pkey;
ALTER TABLE arp_entry_current ADD PRIMARY KEY (device_name, ip);
DROP INDEX IF EXISTS idx_arp_entry_ip;
COMMIT;
EOF

# 4. 回滚旧版本二进制并重启
```

## 📝 注意事项

1. **迁移时间窗口**: 建议在业务低峰期执行，预计停服时间 < 5 分钟
2. **数据增长**: 如果存在真实 IP 冲突，迁移后数据量会增加
3. **监控**: 迁移后关注 PostgreSQL 磁盘空间和查询性能
4. **清理策略**: 可定期清理 `collected_at` 超过 30 天的离线记录
